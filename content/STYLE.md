# タイパ賃貸 記事の文体ガイド

記事を書く前に必ず読む。書いたあとは `node tools/style-check.js` で機械チェックをかける。

調査の前提: SUUMO 5記事、LIFULL HOME'S 5記事、同テーマの他社記事5記事、
AI文章の特徴を扱った日本語記事12本を読んで作った（2026年10月）。

## 大方針

**構造は大手ポータルから借りる。文体は逆に振る。**

SUUMOとホームズの記事は読みやすい。ただしそれは文体ではなく、情報が整理されているから。
文体のほうは「また」「さらに」を1記事に数十回、全部「〜しましょう」で着地、最後に「まとめ」で三点振り返り。
これは AI っぽさの指摘項目とほぼ一致する。真似るとAIが書いたように見える。

人が書いたと感じられた記事に共通していたのは次の3つだった。これを満たすことを最優先にする。

1. **言い切る**。「〜と考えられます」「状況によって異なります」で逃げない
2. **業者側の事情を書く**。借り手には見えないことを明かす
3. **一次体験を入れる**。実際に扱った事例、断られた経験、現場で聞いた話

逆に、専門用語を並べても人が書いたようには読まれない。

## 1. 禁止（書いたら直す）

### 言い回し

- 「〜することができます」→「〜できます」
- 「〜を行います」→「〜します」
- 「〜において」「〜における」→「〜では」「〜の」
- 「〜させていただきます」→「〜します」
- 「〜という形になっています」→「〜です」
- 「〜ではないでしょうか」（読者の気持ちの代弁は、言い切るか書かない）
- 「〜と言えるでしょう」「〜と考えられます」「〜が望ましいでしょう」
- 「一概には言えませんが」「状況に応じて異なります」
- 「まさに」「〜といっても過言ではありません」
- 「非常に」「極めて」「しっかりと」「大幅に」（程度副詞は原則すべて削る）
- 「重要です」「効果的です」「さまざまな」「多様な」（根拠のない評価語）
- 「〜が求められています」「〜が推奨されます」（主体のない受け身）

### 構成

- 冒頭の前置き（「近年、賃貸市場は〜」）
- 「本記事では〜を解説します」という宣言。見出しがその役割を果たす
- 理由やポイントを機械的に3つに揃える。2つなら2つと書く
- まとめで本文を要約し直す。まとめを置くなら、読者が次にやることだけ
- 「素晴らしい新生活を願っています」のような大団円
- 記事本文への自社PRの混入。CTAブロックが別にあるので本文には書かない

### 記号

- マークダウン記号の残留。閉じ忘れた `**` は ビルドが止めるが、書く段階で気をつける
- 欧文ダッシュ（—）、半角スラッシュでの概念並列
- 括弧の多用。補足は別の文に出す

## 2. 文のレベル

| 項目 | 基準 |
|---|---|
| 一文の長さ | 平均35〜50字。80字を超えたら分割 |
| 短い文（20字以下） | 全体の1割以上入れる。「無理です。」のような文でリズムを作る |
| 一段落 | 1〜4文。5文を超えたら割る |
| 文末 | 3種類以上を混ぜる。同じ文末を3連続させない |
| 漢字比率 | 25〜35%。超えたらひらがなにする（事→こと、為→ため、及び→と、従って→だから） |
| カタカナ語 | 1文に1つまで |

### 文末のバリエーション

「です」「ます」だけで押さない。次を混ぜる。

- 体言止め
- 「〜ません」（注意喚起）
- 「〜かもしれません」（本当に不確かなときだけ）
- 疑問形
- 「〜してください」（手順のとき）

ただし「〜しましょう」の連発はしない。大手記事の癖であり、AIの癖でもある。

### 接続詞

**順接の接続詞は原則すべて削る。**「また」「さらに」「そして」「したがって」「そのため」「これにより」。
文のつながりは内容で示し、切れ目は改行で示す。

残すのは逆接だけ。「ただし」「しかし」「一方で」。これも1記事に数回まで。

指示語（これ、それ、この）は実体名に戻す。「これにより」→「申込を先に出すことで」。

## 3. 内容のレベル

### 言い切る

判断を書く。両論併記で終わらせない。

- ✗「メリットもデメリットもあります」
- ○「遠方からの転勤なら内見なしを選んでいい。家族で住むなら内見したほうがいい」

### 業者側の事情を書く

借り手が知らないことを書くと、記事の価値が出る。これは宅建士で実務をやっている人にしか書けない。

例（すでに記事1で使ったもの）
- 間取り図では寸法は分からない
- 管理会社に聞いても寸法は把握していない
- 退去前の部屋は新しく写真を撮ってもらえない
- 退去済みの部屋は管理会社が内見を求めることが多い

### 具体を入れる

1段落に数値か固有名詞がゼロなら、具体性が足りていない。

- ✗「駅から近い物件」→ ○「田無駅から徒歩7分」
- ✗「相場より安め」→ ○「同条件より月4,000円安い」
- ✗「ある調査によると」→ ○「国土交通省の住宅市場動向調査（2025年3月公表）によると」

数値は置くだけにせず、読者にとっての意味を書く。

### 読者を特定する

「お部屋探しをされる方」ではなく、具体的な場面を書く。

- 「内示が出たのが3月中旬、入居は4月1日。内見に行く週末がもうない」

### 分岐と例外を書く

手順を一本道にしない。「審査に落ちたら」「保証会社が◯◯なら」を書く。

## 4. 構造（ここは大手を踏襲する）

| 項目 | 基準 |
|---|---|
| 記事の長さ | 4,000〜6,000字。大手は8,000〜9,000字だが、薄めずに書ける範囲でよい |
| タイトル | 30〜45字。疑問形＋「〜のチェックリスト」のように、問いと中身を両方入れる |
| 導入 | 3〜5文で本題に入る。結論を先に出す |
| 見出しの階層 | h2 と h3 の2階層まで。h4 は作らない |
| 見出しの数 | h2 を4〜8個 |
| 見出しの字数 | 12〜25字。h2は疑問形か問題提起、h3は体言止めを基本にする |
| 表 | 数値・比較・費用内訳は表か箇条書きにする。散文で数字を列挙しない |
| 箇条書き | 3つ以上の並列のときだけ。1項目は15〜40字か、項目名＋1〜2文 |
| 太字 | 1セクションに1か所まで。数値・条件・結論に使う。文を丸ごと太字にしない |
| 用語 | 初出で括弧注か定義文を添える。説明せずに次へ進まない |
| 人称 | 「あなた」は使わない。「〜の方」「〜の場合」で一般化する。一人称も使わない |

### 他社がやっていないこと（差が出るところ）

- 比較表。同テーマ5記事のうち表を使っていたのは1本だけだった
- 宅建士本人が書いていること。大手は外部監修者を立てている
- 業者側の事情の開示

---

## 5. 書いたあとのチェック

1. `node tools/style-check.js` を走らせる
2. 文頭を縦に読む。「また」「さらに」が並んでいたら削る
3. 「まとめ」と冒頭の前置きを消してみる。消して成立するなら不要だった
4. 自分の判断が1つも書かれていなければ、記事ごと見直す
5. 1段落に数値も固有名詞もない箇所を探す

## 6. 事実関係のルール（間違えたことがあるもの）

記事1の修正で判明したこと。次から繰り返さない。

- 間取り図から寸法は読めない。帖数すら書いていない図面もある
- 管理会社に寸法を聞いても分からないと返ってくる
- 退去前の物件では、新しく写真を撮ってもらえない。あるとすれば前回募集時の資料
- 内見なしで申し込めるかは物件による。退去前なら先行申込、退去済みは内見を求められることが多い
- 先行申込（申込のあとに内見）の仲介手数料は、内見なしと同じ扱い（0円または33,000円）
- 浸水リスクは「浸水するか」ではなく想定浸水深で見る。2階なら安全とは言えない
- 耐震基準は築年数から判断できる。1983年以降の完成ならまず新耐震
- 保証会社の初回費用は総賃料（家賃＋共益費）基準
- 鍵交換と火災保険は、物件によっては任意にできる
- 定期借家契約には再契約型がある

### 書かないこと

- 「しつこい営業はしません」
- 担当者の紹介、顔写真
- 宅建士であることの押し出し（1記事に1回まで。それ以上は不自然）
- 「番手」などの業界用語
- 部屋探しを代行するという話。タイパ賃貸は自分で見つけた部屋の手続きを代行する
- 物件ごとの初期費用の概算。正確に出せないものを先に出すとトラブルになる
